# 시뮬레이션·RL 변수 카탈로그

`ProvisionOfSimulationModel` AAS 를 시뮬·RL 의 **단일 진입점**으로 만들기 위한 변수 인벤토리.

**범례**
- `[v3]` cpro_simulation_ver3.py 에만 있음
- `[rd]` redesign/ 에만 있음
- `[공]` 양쪽 공통
- `[직접]` Provision AAS 가 값을 직접 보유
- `[Ref]` Provision 에서 다른 AAS (MP/WWM/HS) 로 Ref 연결 → 거기서 lookup
- `[미반영]` 현재 AAS 어디에도 없음 (cpro_config 또는 시뮬 내부 상태)

---

## §0a. ReferenceElement 표기 규칙 (3 종 명확 구분)

v2 의 모든 `ReferenceElement` 는 `value.keys[0].type` 으로 역할이 결정됨. 통일 = 같은 패턴이 아니라 **이 규칙을 일관 적용**.

| 종류 | `keys[].type` | 의미 | keys 안에 들어가는 값 | 예시 |
|---|---|---|---|---|
| **α 의미 anchor** | `ConceptDescription` | "이 슬롯의 의미는 X. 값은 호출자가 알아서 lookup." | 단일 CD URL (정의) | `CycleTimeSec → CD/CycleTimeSec/1/0` |
| **β 인스턴스** | `GlobalReference` | "이 슬롯은 외부 객체 X 를 가리킨다." | 외부 객체 식별자 (1+ keys) | `MainPcb → CD/PCB_03203204/1/0` |
| **γ 엣지** | `GlobalReference` | "이 노드는 다른 노드 a, b 와 연결된다." | 같은 트리 안 다른 노드 (1+ keys) | `DepPrev → keys=[CD/VD7_10/1/0]` |
| **(Submodel ref)** | `Submodel` | ModelReference, 외부 submodel 통째 가리킴 | submodel id URL | `ExternalRefs.HierarchicalStructures` |

### 적용 규칙
- α 와 β/γ 가 **같은 idShort** 로 등장하면 안 됨 (의미 혼동). 현재 v2 위반 0.
- α 슬롯이 mock-up 단계에서 placeholder 인 경우 (`Worker.Groups[*].Workers[*].WorkerId/SkillLevel`, `OrderQty[*].Qty`, `WorkerCapacity/Capacity`, `CategoryStock[*].MinStock/MaxStock`):
  - 실제 데이터로 채울 때 **각 entry 가 β** 가 되어야 함 (specific WorkerId/PcbCode/StockValue URL).
  - `CycleTimeSec`, `DefectRate`, `MinStock` 같은 "값이 외부 AAS 에 정의되는" 자리는 본질적으로 α 로 영구히 유지 (외부 derive).

### 현재 분포 (v2 점검 결과)
- α: 275 (CycleTimeSec×83, DefectRate×81, MinStock×38, MaxStock×38, Capacity×10, WorkerId×10, SkillLevel×10, Qty×3)
- β/γ: 94 (DepPrev 79 + MainPcb 3 + ThtPcbs 3 + Action 시퀀스 9)
- Submodel ref: 5 (ExistingNodesRef, ExistingActionRef, 외부 AAS 3 개)

## 0. 목표

```
                ┌──────────────────────────────────────────────┐
시뮬 코드  ───→  │  ProvisionOfSimulationModel AAS              │
RL 코드   ───→   │   ├ SimulationConfig  (학습/시뮬 메타)        │
                │   ├ Node[group][pc]  (per-process 파라미터)   │
                │   ├ Action            (DAG 시퀀스)            │
                │   ├ (신규) Ref → MP  (DepType/BOM/...)        │
                │   ├ (신규) Ref → WWM (workstation/worker/skill)│
                │   ├ (신규) Ref → HS  (Archetype/Entity)        │
                │   └ (신규) Policy/Hyper/Reward 등              │
                └──────────────────────────────────────────────┘
                                ↑
                        path_extractor 단일 진입
```

원칙
- 시뮬·RL 코드는 `load_provision_of_simulation_models(...)` 로 받은 객체만 사용
- 다른 AAS (MP/WWM/HS) 도 Provision 의 Ref 를 따라가 가져옴 (직접 load 금지)
- AAS 에 미반영된 항목은 단계적으로 Provision 에 흡수 또는 Ref 화

## 3. Derived 정적 — Factory init 시 1회 계산  [rd]

Provision 에 식 자체를 `SimulationConfig.NormalizationFormula` 로 명시 (값은 init 시 채움):

```
T_REF = MAX_DAYS * (work_end_sec - work_start_sec - break_duration_sec)
E_REF = Σ_(m,pc) rated_kw_of(m,pc) * cycle_time_of[pc] * order[m] / 3600
total_order = Σ_m order[m]
total_worker_capacity = Σ_grp worker_capacity[grp]
pg_to_idx[group]   = 0..K-1
line_to_idx[ws_id] = 0..L-1  (포함 '_UNMAPPED')
all_node_keys      = [(m, pc), ...]
all_bom_items      = ∪_(m,pc) InputBOM.keys()
```

## 4. 동적 변수 — event 기반 갱신식

> Provision 에는 **값**이 아닌 **정의/스키마**만 올림. 예: `SimulationConfig.DynamicVariables[name] = {trigger, formula, units}`.

### 4-A. 재고 (Warehouse)  [공]
```
warehouse.stock[item_code]
  -= qty     @ consume(item, qty)
  += qty     @ restore(item, qty)        # Replenisher 또는 회수

warehouse.violations_count
  += 1       @ consume where stock[ic] < qty
  += 1       @ consume where stock[ic] - qty < CRITICAL_STOCK
```

### 4-B. WIP (재공품)  [공]
```
wip.count[worker_group]
  += 1 @ enter(grp), -= 1 @ leave(grp)
wip.violations_count
  += 1 @ enter where count[grp] > WIP_LIMIT_PER_GROUP
```

### 4-C. 워커 idle  [rd]
```
idle.active[grp]
  += 1 @ acquire(grp), -= 1 @ release(grp)
idle.idle_seconds
  += Σ_grp (capacity[grp] - active[grp]) * dt   @ flush(now)
  where dt = now - last_flush_t
```

### 4-D. 에너지  [공]
```
energy.total_kwh += rated_kw * cycle_time_sec / 3600   @ process end
```

### 4-E. unit 진행 / ready 큐  [rd]
```
units[(m, unit_id)].done : set[pc]
  .add(pc) @ _run_process 종료
units[(m, unit_id)].in_progress
  .add(pc) / .remove(pc) @ start / end

ready_units[(m, pc)] : deque[unit_id]
  .append(unit_id) @ source pc reset 시 또는 후행 pc 가 ready 가 될 때
  .popleft()       @ Dispatcher dispatch

ready 조건:
  - non-JOIN pc : ∃ prev pc ∈ unit.done
  - JOIN     pc : ∀ prev pc ∈ unit.done
```

### 4-F. SMT 라인  [v3]
```
SMTLine.pcb_count[pcb_code] += MAG_SIZE   @ 매거진 완료
SMTLine.solder.stock_g
  -= SOLDER_USE_G  @ stage 사용
  ←  SOLDER_G      @ 만료(now - open_time > SOLDER_VALID_SEC) 또는 부족 시
SMTLine.solder.open_time = now @ reset
SMTLine.stage_active[pc] : bool
SMTLine.stage_events[] : (pc, start, end) 로그
```

### 4-G. THT 외주  [v3]
```
OutsourceTruckPool.truck[]
  .append(mag)  @ 외주 PCB enqueue
  .clear()      @ TRUCK_SIZE 채워 dispatch
OutsourceTruckPool.dispatched_count += 1   @ dispatch
OutsourceTruckPool.in_transit[]            # (truck, depart_t, arrival_t)
OutsourceTruckPool.truck_log[]             # delay 포함 로그
```

### 4-H. 설비 고장 / 결근  [v3]
```
smt_broken[pc]
  ← True   @ Bernoulli(SMT_BREAKDOWN_PROB)
  ← False  @ MTTR(RESOURCE_MTTR_HR[pc]) 시간 경과
idle.absent_groups : set[worker_group]
  .add(grp)    @ Bernoulli(WORKER_ABSENT_PROB) 출근 체크
  .remove(grp) @ 다음 day 시작
```

### 4-I. 통계 / 진척도  [v3]
```
stats['smt_defect'] += 1 @ SMT end ∧ rand < DefectRate
stats['aoi_defect'] += 1 @ AOI end ∧ rand < DefectRate
stats['pcb_done']   += MAG_SIZE @ 매거진 완료
```

## 5. KG 노드 동적 feat — `Dispatcher.tick()` 마다 갱신  [rd]

```
node.is_ready             = ready_units_count[(m,pc)] > 0
node.worker_util          = worker_resources[worker_of(m,pc)].count / capacity
node.bom_satisfied        = ∀(ic,q) ∈ InputBOM[m][pc] : warehouse.stock[ic] >= q
node.time_since_eligible  = sim_now - _eligible_since        if is_ready
                           = 0                                otherwise
```
`_eligible_since` : 처음 is_ready=True 가 된 시각, False 가 되면 -1 로 리셋.

정적 슬롯 (Factory init 시 1회):
`cycle_time_sec, defect_rate, rated_kw, bom_count, process_group_idx, line_idx, is_join`

## 6. RL state_vec — critic 입력 (graph-level)  [rd]

```
progress_t        = sim_now / T_REF
completion[m]     = done_n[m] / order[m]                          # K dim
caller_vec        = gnn.line_emb(line_to_idx[caller_line_id])     # 4 dim
global5 = [
    warehouse.violations_count / total_order,
    wip.violations_count       / total_order,
    energy.total_kwh           / max(sim_now+1, 1),
    idle.idle_seconds          / max(sim_now+1, 1),
    smt_broken_ratio,                                              # 현재 0.0 placeholder
]
worker_util[grp]  = 1 - worker_resources[grp].count / capacity[grp]   # W dim

state_vec = [progress_t] ++ completion ++ caller_vec ++ global5 ++ worker_util
```

## 7. GNN 입력 H — per-node, 17-d  [rd]

```
H[n] = concat(
    H_static_scalar[n] = [cycle_time_sec, defect_rate, rated_kw, bom_count, is_join],  # 5
    pg_emb(process_group_idx[n]),                                                       # 4
    line_emb(line_idx[n]),                                                              # 4
    H_dynamic[n] = [is_ready, worker_util, bom_satisfied, time_since_eligible],         # 4
)                                                                                       # 17

adj 5 종 (KG 빌드 시 고정):
  R_FWD_JOIN  prev → pc, pc 가 JOIN
  R_FWD_SEQ   prev → pc, pc 가 non-JOIN
  R_BWD_JOIN  pc → prev, pc 가 JOIN
  R_BWD_SEQ   pc → prev, pc 가 non-JOIN
  R_SELF      자기 자신
```

## 8. RL action / mask  [rd]

```
caller_line_id ∈ factory.line_to_idx.keys()    (사전순 sequential)
mask(line_id) = ready_mask
              AND line_filter_mask(line_idx)
              AND bom_satisfied_mask           # (N,) bool

action ~ Categorical(softmax(node_scores.masked_fill(~mask, -inf)))
→ chosen_idx → node_keys[chosen_idx] = (m, pc)
→ unit_id    = ready_units[(m,pc)].popleft()
```

## 9. RL reward — dense 4 + terminal 3  [rd]

```
Δstock = warehouse.violations_count - prev.stock
Δwip   = wip.violations_count       - prev.wip
Δdone  = sum(unit.done==total_pc[m]) - prev.done
Δidle  = idle.idle_seconds          - prev.idle

r_stock_short = -Δstock / total_order
r_stock_over  = -Δwip   / total_order
r_done        =  Δdone  / total_order
r_idle        = -Δidle  / (total_worker_capacity * T_REF)

r = REWARD_W_STOCK_SHORT * r_stock_short
  + REWARD_W_STOCK_OVER  * r_stock_over
  + REWARD_W_DONE        * r_done
  + REWARD_W_IDLE        * r_idle

# terminal
r_make    = -makespan / T_REF
r_energy  = -energy.total_kwh / E_REF
r_success = 1.0 if Σ_m done[m] == total_order else 0.0
r += REWARD_W_MAKESPAN * r_make
   + REWARD_W_KWH      * r_energy
   + REWARD_W_SUCCESS  * r_success
```
