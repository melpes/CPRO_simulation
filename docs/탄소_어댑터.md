# 탄소 어댑터 (carbon.py) — 현재 삽입 위치 및 MCF 확장 대응

## 1. 목적

생산 활동을 **탄소배출량(kgCO2e)** 으로 변환하는 지점을 한 모듈(`carbon.py`)로 모은다. 과기대(생산량)와 달리 탄소 수식·계수는 **에코앤파트너스(ECO)** 가 추후 전달하므로(MCF → PCF), 어떤 형태로 오든 **이 한 파일만 고쳐** 반영할 수 있게 한다.

> MCF = Manufacturing Carbon Footprint. 현재 시뮬은 **전력(에너지)** 만 탄소 proxy로 쓴다.

## 2. carbon.py 구조

```python
EMISSION_FACTOR_KWH = 1.0                       # kgCO2e/kWh (Scope2 전력). proxy=1.0 → 동작 보존. ★ECO 교체점

def from_energy(energy_kwh):                     # 전력 배출원
    return energy_kwh * EMISSION_FACTOR_KWH

def total(energy_kwh):                           # Σ 배출원 (현재 = 전력만)
    return from_energy(energy_kwh)
```

- **배출원 변환 함수의 모음** 이다. 현재는 전력(`from_energy`) 하나.
- `total()` 이 "총 배출 = Σ 배출원" 의 **집계 진입점**. 각 모듈은 `import carbon` 후 `carbon.total(...)` 호출.
- run 주입이 아니라 **각 모듈이 직접 import** (배출계수 고정이라 주입 불필요).

## 3. 현재 삽입 위치 (어디서 carbon을 부르는가)

| 위치 | 호출 | 의미 |
|---|---|---|
| `simulation.py` `CproSimEnv.potential()` | `carbon.total(EpisodeEnergyKwh) / carbon.total(_max_episode_premium)` | 보상 **W2 항** = 정규화 탄소 비율 |
| `export.py` `build_payload()` | `carbon.total(energy)` | 외부 전달 페이로드의 `carbon_kgco2e` |

- **에너지 회계(kWh)는 그대로 유지**: `path_extractor.RuntimeVariables.EpisodeEnergyKwh`(공정별 `RatedPowerKw×CycleTimeSec` 누적, AAS-grounded)가 에너지를 계산한다. carbon.py는 그 kWh를 **탄소로 변환만** 한다(관심사 분리).

## 4. 동작 보존 원리

W2 항 = `total(E) / total(E_max)`. 선형 단일 배출원(`E×factor`)이면 분자·분모에서 **factor가 약분**되어 비율 = `E / E_max` — 기존 에너지 기반 W2와 **정확히 동일**. 즉 `EMISSION_FACTOR_KWH` 를 바꿔도 (선형인 한) 보상·정책은 불변. proxy 상태에서 회귀 0.

> 검증: factor 1.0 ↔ 0.4541 에서 potential 동일.

## 5. MCF 확장 시 대응 (ECO 도착 시)

ECO 전달 형태별로 **carbon.py 한 곳** 에서 처리한다.

| ECO가 주는 것 | 대응 | 코드 무수정 범위 |
|---|---|---|
| **① 전력 배출계수** (kgCO2e/kWh) | `EMISSION_FACTOR_KWH` 값 교체 | simulation/run/export 전부 |
| **② 비선형 전력 수식** | `from_energy()` 본문 교체 | 〃 |
| **③ 전력과 같은 레벨의 새 배출원** (설비·공정 가동 시 직접 탄소 — 가스·냉매·연소 등) | `from_X(...)` 함수 추가 + `total()`에 합산 항 + (엔진이 해당 활동량 누적·전달) | simulation은 누적 1줄·`total` 호출만 |
| **④ 계수를 AAS로 제공** | `path_extractor`가 추출 → `run`이 `carbon`에 주입(정책주입 승격) | carbon은 인자만 받게 |

**핵심**: ①②는 carbon.py만. ③은 새 배출원이 "전력과 같은 레벨"(=공정/설비 가동 기반)이므로, 엔진이 그 활동량을 누적해 `carbon.total(...)`에 넘기는 최소 결선만 추가 — 자재 LCA(임베디드 탄소)와는 다른 *가동 기반* 배출이다.

## 6. 후속

- W2 idShort는 `W2_Energy` 유지(에너지가 탄소 기반, 현 동작 동일). ECO 실모델 결합 후 `W2_Carbon` 개명 검토.
- W2가 *실질적으로* 탄소를 반영(에너지와 갈라짐)하려면 ECO 모델이 **비선형 또는 다배출원**이어야 한다. 그 전까지는 에너지 proxy로 동작.
