# 모듈 재구성 — KETI 파이프라인 정합

## 1. 배경 / 목적

시뮬레이션·강화학습 코드가 기술 레이어(`domain` / `observe` / `nn` / `sim` / `factory`) 기준으로 쪼개져 있어, KETI 과제의 **데이터 흐름**과 모듈 경계가 어긋났다. 과제 흐름은:

```
AAS 파싱 → 공정 선후관계(KG) → 자재·작업자(MBOM·재고·발주·공정시간) → 학습·시뮬 구동 → 외부 전달
```

이 5단계에 1:1로 읽히도록 모듈을 재배치하고, `cpro_` 접두어를 제거해 일반화된 이름으로 정리했다.

## 2. 모듈 구조 (KETI 5단계 매핑)

| 단계 | 모듈 | 역할 |
|---|---|---|
| ① 입력 (AAS contract) | `path_extractor.py` | AAS JSON → 도메인 객체 변환 **단일 창구**. JSON 직접 파싱 금지, 모든 AAS 접근은 여기로. |
| ② 공정 KG | `knowledge_graph.py` | `GraphNode`/`GraphEdge`/`KnowledgeGraph` — 공정 선후관계(DepPrev/DepType) 그래프 + `ready_queue`. 조립만/＋SMT 포함은 `build`에서 결정. (AAS·simpy·torch 무관 순수 도메인) |
| ③ 공장 자원 | `warehouse.py` | `StockItem`/`Warehouse`/`_StockRouter` — MBOM·min/max stock·발주(replenish)·PCB 라우팅. (순수 도메인) |
| ④ 학습·구동: 시뮬+RL | `simulation.py` | `CproSimEnv`(simpy 이산사건 env·디스패처·smt·reward·state_vec) + 관측 producer + `GraphModule`/op + `PPOAgent` + `train`. **RL의 env로 기능하는 simpy와 학습을 한 모듈에** 둔다. |
| ④ 학습·구동: 탄소 | `carbon.py` | 활동(에너지 등) → 탄소(kgCO2e) 변환 seam. (별도 문서 `탄소_어댑터.md`) |
| ⑤ 외부 전달 | `export.py` | 최적해 → 외부 페이로드(JSON) + `send()` stub. (실 API 계약 미정) |
| 진입점 | `run.py` | AAS 로드 + `build_simulation`/`build_agent` wiring + `__main__` 학습 실행. **유일한 조립/주입 지점**. |
| 보조 | `smt.py` | SMT 라인 PCB 보급 stub(`pcb_supply`) — 실 설비 미주입 시 fallback. |

> `cpro_plan_cell.py`(셀 재구성 RL PoC)는 핵심이 아니므로 `scratch/plan_cell.py`로 보관.

## 3. 데이터 흐름

```
[제품 AAS: MODEL_A/B/C(HS,MP)] ┐
[WWM: 작업자/라인]              ├─→ PSM ─→ path_extractor.py ─┬─→ knowledge_graph.py (공정 연결)
[PO: 수량·등록일·납기일]        ┘                              ├─→ warehouse.py     (재고 분류·정책)
                                                              ├─→ reward 계수      (RewardWeights)
                                                              └─→ RL 아키텍처      (ModelArchitecture)

run.py ── build_simulation ──→ CproSimEnv(simulation.py)
       └─ build_agent      ──→ PPOAgent (simulation.py, AAS 계산그래프 해석)

CproSimEnv 내부: knowledge_graph(공정) + warehouse(자재) + smt(PCB) + carbon(탄소) + reward(Φ)
RL: GNN이 knowledge_graph 인코딩 + state_vec 관측 → PPO

run.py ──→ export.py (최적해 페이로드)
```

## 4. 주요 변경 / 호환

- **facade 제거**: 구 `simulation_ver1.py`(re-export)는 삭제. AAS `ModelArchitecture`의 Op 경로 문자열(`simulation_ver1.PPOAgent` 등)을 `simulation.*`로 갱신했고, `mod_run/` 도구의 import를 실제 모듈로 재배치했다.
- **진입점 단일화**: 도구는 `import run as cf`(=`build_simulation`/`build_agent`)와 `import simulation`만 사용. wiring 중복을 한 곳(run.py)에 모았다 — 없애면 ~240줄이 도구마다 부활하므로 유지.
- **AAS 단일 창구 유지**: 새 모듈도 `path_extractor`만 읽는다. JSON 직접 파싱·특정 ID/코드값 분기 금지.
- **주석 분리**: 코드 본문의 `#` 주석·docstring은 제거하고 내용은 `docs/CODE_NOTES.md`에 보존(인코딩 선언만 유지). 새 코드도 동일 컨벤션.

## 5. 검증

`run.build_simulation` + `build_agent` + `train` 1 에피소드가 재구성 전후 동일 동작(throughput/makespan/energy 일치), AAS Op resolve(`simulation.PPOAgent`) 정상, mod_run smoke 통과를 확인했다.

## 6. 후속 / 주의

- `scratch/*` 실험 도구는 구 모듈명 import가 남아있을 수 있다(best-effort 범위 밖).
- 구 메모리/CLAUDE.md에 `cpro_factory` 등 옛 이름 잔존 — 참조 시 본 구조로 환산.
