### 3-2. 그룹 정의 (※process_group)

`[통합xlsx].PROCESS_FLOW` R0 메모 + 사용자 보강 (2026-05-27).

| 그룹 | 정의 | 운반수단 (출력 → 다음 그룹) |
|---|---|---|
| **MODULE** | **전자모듈(PCB+센서+렌즈) 조립 작업** — F/W·MAC 입력, SENSOR BOARD 조립, FOCUS SETTING. 그룹 내부 이동 = Tray 20/40 EA, 그룹 출력(→SET) = Tray 10~20 EA. `[QA]` 의 "반조립 모듈" 표현이 이 그룹의 결과물 (회의록은 "카트" 라 의역) | Tray 10~20 |
| **SEMI** | **기구(케이스) 반조립** — Main Board 없이 가능한 기구 조립. DOME 타입 = Upper + Bottom / BULLET 타입 = Front + Rear / NVD = Front + Rear + Set 외장 부품 | **대차** 60~100 SET (기본 80) |
| **SET** | **완조립** — MODULE 결과(전자모듈) + SEMI 결과(기구) 합쳐 카메라 본체 완성. Gimbal Assy, Set Assy, Side Cover, Camera Test 등 | **대차** (→AGING) |
| **INSP** | 검사 — Camera Test, **Aging Test** (2~4h, 30포트), OQC | **대차** (→PACK) |
| **PACK** | 포장 (박스 / 라벨 / 카톤박스 / 진공) | (출하) |
| **RMA** | 불량 수리 — 수리 후 해당 공정 재투입 | 대차 (불량 수량) |
| **SMT** / **SMT_SHARED** | SMT 라인 (전 모델 공통) | 컨베이어 (내부) / 대차 (Unloader→AOI→매거진→Loader 2차면) |
| **LOGISTICS** | 외주 수삽 등 비-공장-내부 노드 (`THT_*`) | 트럭 |

> **★ "MODULE" vs "SEMI" 혼동 주의**: 둘 다 "조립" 인데 의미 다름.
> - **MODULE = 전자 모듈** (PCB·센서·렌즈)
> - **SEMI = 기구 반조립** (케이스·하우징)
> - **SET = MODULE + SEMI** 결과를 합쳐 완성된 카메라.
>
> 회의록 5/20 R1 의 "**카트(반조립 모듈, 세트 조립품)**" 에서 "반조립 모듈" 은 **MODULE 그룹의 결과물 (FOCUS 거친 전자 모듈)** 을 가리킴 (회의록 작성자 의역). `[QA]` / `[v1.1]` / 이문수 부장 본인은 "트레이" 로 통일 표기 — 본 문서도 트레이로 통일.

### 3-3. 의존 타입 (dep_type)

- **SEQUENCE**: 단일 선행 공정 → 다음 공정. `_predecessors` 가 1개일 때 그 공정이 done 이면 ready.
  - 단, `simulation_ver1.py:99` `ready_queue()` 의 분기 보면 `DependentSequence` 는 `any(d in completed)` 로 동작 — 선행 중 하나라도 끝나면 진입 가능.
- **JOIN**: 다중 선행 공정. `all(d in completed)` — 전부 끝나야 진입.
- **FORK**: 정의는 있으나 PROCESS_FLOW 에 사용 사례 없음 (`[통합xlsx]` R0 메모만).

### 3-4. SMT 라인 토폴로지 (ALL — 공통)

> ⚠️ **SMT 영역은 `[통합xlsx].PROCESS_FLOW` 구조를 따르지 않고 신규 설계 예정**. 이하 정보는 **정보조사 결과**로만 보존되며, 시뮬 노드 구조·디스패처 정책 등은 별도 작업에서 결정.

회의록 R1 / `[통합xlsx]` / `[v1.1].SMT 공정` 에서 일치 확인됨.

```
양면 작업:
  Loader → Screen Printer → SPI → Mounter(High Speed) → Mounter(Multi) → Reflow → Unloader → AOI → Loader (2차면)

단면 작업:
  Loader → Screen Printer → SPI → Mounter → Reflow → Unloader → AOI → (외주 수삽)
```

`[통합xlsx]` 의 SMT 노드 (라인별 L1/L2):

| ProcessCode (L1/L2) | 공정 | CycleTime |
|---|---|---|
| `SMT_LOADER_L1` / `_L2` | PCB 투입 | 2초 |
| `SMT_PRINTER_L1` / `_L2` | Screen Printing | 43초 |
| `SMT_SPI_L1` / `_L2` | SPI 인쇄검사 | 15초 |
| `SMT_MOUNTER_H_L1` / `_L2` | Chip Mounter (4M Base) | 80초 |
| `SMT_MOUNTER_M_L1` / `_L2` | Multi Mounter | 45초 |
| `SMT_REFLOW_L1` / `_L2` | Reflow Soldering | 410초 |
| `SMT_UNLOADER_L1` / `_L2` | PCB 적재 | 5초 |
| `SMT_AOI` | AOI 외관검사 (양 라인 공용, JOIN) | 30초 |

**1 Board 기준 평균 = 620초** (`[v1.1]` SMT 공정 시트), AOI 30초 별도.

> **라인 1과 2 동시 동일 모델 X**: `[v1.1]` 메모 — "1 line 당 한 가지 Board만 생산 진행하며 여러 종류가 동시에 투입되지는 않음".
> **양면 작업 메모**: `[v1.1]` — AOI review 이상이 있는 경우 별도 처리 필요.

### 8-6. PCB SelfManagedBOM 정책

`[전사_100836]` 55:23~57:55: **"PCB는 한 개씩 장착되는 게 아니라 가이드가 붙어 있어, 이동·실장 시 가이드가 필요"**.

→ **PCB 는 어레이 단위로 생산**됨. 한 가이드(외곽 캐리어) 위에 여러 PCB 가 함께 SMT 실장된 뒤, 라우터에서 V-cut 으로 절단·분리하여 개별 PCB 가 됨. 가이드는 절단 후 폐기물.

#### 어레이 단위 (확정 — 2026-05-27)

| 항목 | 값 |
|---|---|
| **1 가이드(어레이)당 PCB 수** | **6 PCB** (모든 모델·모든 PCB 종류 공통) |
| **SMT cycle_time 기준** | **어레이 기준** — PROCESS_FLOW 의 SMT CT (Loader 2s, Printer 43s, ... , Unloader 5s, AOI 30s, 1 보드 평균 620s) 는 **어레이 1장 처리 시간** |
| **Throughput 환산** | SMT 1 cycle 완료 = **6 PCB 산출** |
| **1 매거진** | 40 어레이 = **240 PCB** 환산 |

> 모델 1대 생산에 필요한 PCB 수가 N 개라면 SMT 라인 통과 어레이 수 = `ceil(N / 6)`. throughput 계산에 직접 영향.

#### 절단 / 후처리

- **일반 PCB**: 라우터에서 V-cut(제봉선) 절단. 사각 어레이는 원형 칼날 2개로 절단 (`[전사_100836]` 56:54).
- **알루미늄 PCB**: 라우터 못 사용 → **2층에서 수동 컷** (`[전사_100836]` 1:04:22). 가시광선 LED 보드라 열 발생 → 라우터로 자르면 응력으로 부품 떨어짐.
- **가이드**: 절단 후 폐기물 (업체 위탁 처리).
- **PCB 자체**: 금 수거 업체 → 소각 → 금 채취 (`[전사_100836]` 56:35).

#### SelfManaged 별도 창고

`simulation_ver1.py:204` 의 `_StockRouter` = 메인(CoManaged) + PCB(SelfManaged) 분리 구조.

→ SMT_PCB (prefix 032/039/049) 는 PCB 별도 창고 (`cpro_pcb` 코루틴) 로 라우팅. **현재 `cpro_pcb.pcb_supply` 코루틴은 미작성 — 사용자 다음 작업 영역 (SMT 신규 설계) 에서 함께 작성 예정.**

## § 9. SMT 공정 상세 (정보조사 — 시뮬 구조 신규 설계 예정)

> ⚠️ **이 섹션 전체는 SMT 신규 설계를 위한 정보조사 결과**. 시뮬 노드 구조·이벤트 흐름·디스패처 정책은 별도 작업에서 사용자가 직접 작성. 본 섹션의 사실들은 그 설계의 입력 근거로 사용.

### 9-1. SMT 라인 구성 (`[전사_100836]` 18:10 + `[SMT구조도]`)

- **SMT 2개 라인** (라인1, 라인2) — 동일한 PCB 흐름 처리, 독립 가동.
- 양 라인 모두: Loader → Screen Printer → SPI → 컨베이어 → Mounter (High Speed → Multi) → 컨베이어 → Reflow → 컨베이어 → Unloader → (AOI 공용).
- 1라인과 2라인 차이: 일부 설비 모델만 다름 (Reflow 62.6 vs 47.7 kW, SPI 다름).

### 9-2. 점수(칩수) 분배 (`[전사_100836]` 14:52)

- "점수(칩수) 많으면 1번 라인에서 다 안 되면 2번 라인에서". 
- 베트남 공장은 작은 마운터 2대 운영 (큰 마운터는 한국).

### 9-3. 양면 작업 흐름 (`[QA]` 2.4)

```
1차면:  Unloader → AOI → 매거진 적재 후 AOI 옆 '1차면 완료분 보관 구역'에서 보관
        (1차면 전량 완료까지 대기)
2차면:  1차면 전량 완료 후 대차로 메거진 1~2개 단위 Loader 이동 → 2차면 SMT 진행
```

> **현재 PROCESS_FLOW 의 SMT 토폴로지는 단일 통과 모델링** — 양면 시 1차/2차면 분리 모델링은 아직 미반영. § 99 참조.

### 99-3. 시뮬 코드 직접 반영 권장 사항

`simulation_ver1.py` 구조 기준 우선순위:

1. **MOQ 기반 발주 시스템 신설**: 현재 `consume()` 의 `MinStock * OrderRatio` 발주점 → `[QA]` MOQ 기반으로 진화. *deadlock 1차 해소는 A안 (replenish 도착 시 발주점 재검사) 적용 완료 — § 99-2 #23*
2. **OQC 노드 추가**: AGING → OQC (5% 샘플링) → PACK 순서 반영 — AAS 템플릿 확장 필요
3. **RMA 재투입 흐름**: defect 발생 시 RMA 로 라우팅 → 수리 후 해당 공정 재시작 — AAS 템플릿 확장 필요
4. **SMT 양면 작업**: 1차면 / 2차면 분리 토폴로지 (또는 양면 PCB 에 대해 cycle_time × 2 적용) — SMT 신규 설계 영역
5. ~~AAS qualifier 추가: AgingDuration~~ **완료 (2026-05-27)**: `DepWaitSec` 도메인 타입으로 일반화 (`AgingTestDurationSec=10800`). PcbType/CameraType 은 여전히 미반영 (SMT 신규 설계 시 검토)
6. **SMT 라인 자동 라우팅**: "점수 많으면 1번 라인 안 되면 2번 라인" — § 9-2 정책을 dispatcher 에 반영
7. **시뮬 성능 최적화**: `_predecessors` 캐싱 + `produce_unit` polling 60s → wake-up event 메커니즘. 현재 wall-clock 4~7분 (300 unit) — 1분 이하 단축 가능
