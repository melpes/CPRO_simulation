# 시뮬레이션 학습 실험 결과 (2026-06-01)

`simulation_ver1.py` RL(PPO/GNN) 보상 확장 + 1일→3일 horizon + 성능 최적화 후
**학습이 실제로 greedy 를 능가함을 검증**한 세션 기록. 산출물은 `mod_run/result/runs/`
(gitignore) 에 있고, 진실의 원천은 코드 본문 — 본 문서는 핵심 수치·결정·발견 요약.

## 1. 보상 확장 (W3/W4/W6 추가 + 에너지 [0,1] 재정규화)

- **배경**: ver1 의 potential-based shaping(`r_t=Φ(s_{t+1})−Φ(s_t)`)이 throughput(W5)·time(W1)·
  energy(W2)만 반영. W3(재고초과)·W4(재고부족)·W6(유휴)는 `state_vec` 관측만, 보상 미반영.
  원인은 **카운터 미배선** — `path_extractor` 에 누적 메서드(`StockShortageCount`/
  `StockOverflowCount`/`IdleViolationCount`)가 있었으나 ver1 이 호출 안 함(dead code).
- **배선**: `CproSimEnv.run` 의 `_watch()` 30s 틱(근무시간 게이트)에서 3 카운터 누적 →
  `potential()` 에 단조 카운터로 추가. 순간값이 아닌 **누적**이라야 중간 위반이 telescoping
  에서 상쇄되지 않음. 고정 분모(품목/워커수 × 1일 근무틱)로 ~[0,1].
- **에너지 [0,1] 수정**: 기존 `total_energy / (1사이클 프리미엄)` 이 분자에 하루치 idle 포함
  → 비율 ~38 폭발, W5 를 **152× 지배**. → `MaxEpisodeEnergyKwh` 를 **전 unit 완성 시 active
  프리미엄**으로 재정의(`path_extractor`), 에너지 항 = `EpisodeEnergyKwh / max_premium ∈ [0,1]`.
  idle baseline 은 makespan 비용이라 **W1_Time 이 담당** → 에너지에서 제외(이중계상·지배 해소).
- **균형 검증 (qty=100, 1일)**: 6항 모두 throughput 의 1.0~1.65× (지배 없음).
  주의: **qty 고정 시** horizon 늘려도 비율 보존(전 항 시간 비례). **qty 키우면 안 됨** —
  qty≥500 은 1단계 job 범람으로 throughput 0 붕괴 + W5 정규화(total_target) 희석.

## 2. 학습 horizon = 3일 (1일은 학습 불가)

- **1일 검증(60ep)**: 전 지표 flat, ev 음수(critic 무학습). 원인:
  - **MODEL_B = 0 구조적** — `BT5_42` 24h 본드(DepWaitSec=86400)가 1일 에피소드 전체를 먹어
    B 가 **1일 내 완성 물리적 불가**.
  - A/C 는 1일 capacity-bound → ready job 재배열로 일일 총량 안 바뀜.
  - 지배 페널티(재고부족)는 공급 리드타임 발 외생 → advantage ~0.
- **3일 채택**: `EPISODE_DURATION_SEC = 3*86400`. B 의 24h 본드가 들어가 B 생산 가능 +
  throughput 정책 민감 → 학습 leverage 확보. 평가는 **전량완료(300 unit)** 기준.

## 3. Track F — produce_unit 폴링 제거 (49× 가속)

- **문제**: `produce_unit` 의 `if not outstanding: yield timeout(60)` — BOM 부족으로 다음
  공정 제출 불가 시 60s 마다 깨어 `ready_queue` 전체 재스캔(헛스캔 수백만 회).
- **이벤트 누락 없음 분석**: 폴링 분기는 **오직 재고 부족(BOM)** 시 도달(선행완료·본드경화·
  워커대기는 모두 `AnyOf(outstanding)` 이벤트 기반). 유일한 unblock 이벤트 = **재고 입고(replenish)**.
  consume 는 재고를 줄이기만 해 unblock 안 함.
- **수정**: `_stock_wake` broadcast 이벤트(replenish notify 콜백, 재귀 발주도 전달) 로 교체.
  `_predecessors` 역방향 맵 1회 캐싱(§99-3 #7) 추가.
- **검증**: greedy 3일 **244s → 5s (49×)**. 결정성(seed 동일 → 동일 결과)·정확성(집계 카운터
  <0.3% 일치) 확인. sim 이벤트 시각 불변(폴링 헛스캔만 제거).

## 4. 학습 결과 — trained 가 greedy 능가 ✅

3일 horizon 60ep 학습 후 **결정론(argmax) + 전량완료** eval (`_capture_eval.py`):

| 정책 | makespan | 유휴(IdleViolation) | 에너지 | 재고부족 |
|---|---:|---:|---:|---:|
| greedy | 134.0h | 278255 | 30461 | 416208 |
| **trained** | **113.0h (−15.7%)** | **241219 (−13%)** | **27890 (−8%)** | 402302 (−3.3%) |

- **rollout 지표는 flat 이었으나(3일 truncation + 탐험 샘플링), 결정론 full eval 이 진짜 정책 실력**
  — 거기선 명확히 개선. `ev 0.52→0.70` 상승이 조기 신호였음(critic 이 구조 학습).
- 개선 방향이 보상 설계와 일치: W1(시간)·W6(유휴)·W2(에너지) 개선, **W4(재고부족)은 거의 불변
  (외생분이라 정책이 못 줄임 — 예측대로)**.

## 5. idle 감소 원인 분해 — 전부 MODEL_B

- **idle/tick 거의 불변** (greedy 52.7 vs trained 51.5, 58슬롯 중). 즉 **패킹이 좋아진 게 아니라
  makespan 단축**(work-tick 5281→4680)으로 idle 총량이 준 것. 에너지 −8% 도 idle baseline↓ 영향.
- **모델별 마지막완료**: A=57h, C=62h **불변**(greedy=trained). **B 만 134.0→113.0h (−21h)**.
  라인별 busy worker-h 도 모델별 완전 동일 → **총 작업·분배 불변, B 의 타이밍만 변함**.
- 즉 학습 정책의 실질 = **막판 홀로 남는 MODEL_B 를 21h 빨리 통과** → makespan↓ → idle·energy↓.
- 구조 참고: 58슬롯 중 ~52 유휴/틱 = 라인이 **워커 부족이 아니라 의존성·본드 대기**에 묶임(over-resourced).

## 6. "B 우선" 휴리스틱은 효과 없음 — RL 은 비자명 스케줄 학습

모델 우선순위 편향(`scratch/_bias_makespan.py`, 전량완료):

| 정책 | makespan |
|---|---:|
| greedy(FIFO) | 134.0h |
| B우선(B>A>C) | 133.1h (A를 57→65h 밀어내기만, B 거의 불변) |
| trained | **113.0h** |

- **단순 모델 우선순위로는 makespan 거의 안 줄어듦** (B 병목은 워커 경합이 아니라 **본드 24h
  (워커-free 병렬) + 마지막 B unit 이 본드 도달하는 전체 파이프라인 흐름**).
- trained 의 21h 이득은 stage-level 미세 흐름 최적화(틱당 워커 충전율 ↑)에서 옴 —
  **단순 휴리스틱으로 재현 불가 → RL 이 비자명한 스케줄을 학습했다는 증거**.
