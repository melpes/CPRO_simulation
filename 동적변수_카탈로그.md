# 동적 변수 카탈로그 — 우선순위 뷰

`simulation_ver0.py` 구현 시 simpy / RL / PPO / GNN 각 측면에서 **빠지면 동작 안 함 → 핵심 → 보조 → 진단/모니터** 순으로 정렬. 위에 있을수록 먼저 구현 필요.

표기:
- `var` — 변수명
- `←` — 입력 파라미터 (계산/갱신에 필요한 다른 값)
- 보유 후보 클래스는 ver0 에서 확정 — 여기선 cpro_ver3/redesign 기준

---

빠지면 시뮬레이션 자체가 안 굴러감.

| 11  | `aoi_res.count`                                                         | AOI request/release                                                  | SMT-AOI 공유 자원  |
| 12  | SMT 라인 `_res[stage].count`, `assigned_model`, `mag_buf`, `stage_active` | 보드 stage 점유, `_smt_schedule`, `MAG_SIZE`, 외주 도착                      | SMT 7-stage 흐름 |
| 13  | `smt_broken[pc]`                                                        | `SMT_BREAKDOWN_PROB` random (600s 주기), `MTTR_HR[pc]`                 | 설비 고장 대기       |

| 16  | `OutsourceTruckPool.{truck, in_transit, dispatched_count}`              | `add_board`, `TRUCK_SIZE`, `THT_OUTSOURCE_SEC`, `THT_DELAY_*` random | THT 외주         |
| 17  | `SolderCream.{stock_g, open_time}`                                      | `SOLDER_G`, `SOLDER_USE_G`, `SOLDER_VALID_SEC`, env.now              | 솔더 페이스트 잔량     |

# 2. RL — 강화학습 신호 (알고리즘 무관)

PPO/SAC/A2C 등 어떤 알고리즘이든 필요. **이 층은 GNN 도 PPO 도 가정 X**.

| # | 변수 | 입력 ← | 역할 |
|---|---|---|---|
| 1 | `reward` | delta 6항 × `RewardWeights.{W1..W6}` | 강화 신호 |
| 2 | `state_vec` | `progress[m]/order[m]`, `1 - count/cap`, `energy.total/now`, `now/T_REF`, `wh.violations/total_order`, `wip.violations/W`, `idle_pen/now`, `smt_broken_ratio` | 정책 입력 |
| 3 | `ready_mask` | `KG.nodes[*].is_ready` | 행동 후보 마스킹 |
| 4 | `action_idx` | 정책 sampling 결과 | 선택된 행동 |
| 5 | reward delta tracker (`_prev_reward_t/kwh/wip_viol/stock_pen/done/idle_pen`) | 직전 호출 시점의 누적값 스냅샷 | delta 계산 기준 |
| 6 | `wh.violations_count` | `stock[c] < min/critical` 비교 누적 | stock penalty 원료 |
| 7 | `wip.violations_count` | `wip[g] > cap[g]` 비교 누적 | wip penalty 원료 |
| 8 | `idle.total_idle[group]`, `worker_idle_penalty()` | `(cap - active) × _work_seconds_between` 누적, threshold 필터 | idle penalty 원료 |
| 9 | `energy.total` | `RatedPowerKw × cycle_time / 3600` 누적 | energy delta 원료 |
| 10 | `done_total` (= Σ `stats[f'{m}_done']`) | unit 정상 종료 누적 | done delta 원료 |
| 11 | `_reward_decomp_sum[6]` | 매 reward() 호출의 `Wi × ri` 누적 | 보상 분해 추적 (학습 진단) |

# 3. PPO — PPO 알고리즘 특화

PPO 가 아닌 다른 알고리즘으로 갈아끼우면 빠지거나 다른 형태로 대체.

| # | 변수 | 입력 ← | 역할 |
|---|---|---|---|
| 1 | `agent.buf` | `(state, embedding, action, reward, log_prob, value, mask, model_id)` 매 step | 트랜지션 버퍼 |
| 2 | `log_prob` | `dist.log_prob(action)` (선택 시) | clip ratio 계산 (old policy) |
| 3 | `value` | `critic_head(encoder(cat(state, graph_embed)))` | GAE / critic loss 기준 |
| 4 | `advantages` | `δ_t = r + γV_{t+1} - V_t`, `GAE = δ + γλ·GAE_{t-1}` | actor loss 계수 |
| 5 | `ep_rewards` | `sum(rewards in buf)` 매 update 끝 | 수렴 판단 (`CONV_WINDOW`, `CONV_THRESHOLD`) |
| 6 | `ep_rewards_decomp` | `_reward_decomp_sum` 스냅샷 매 ep | 학습 진단 (어느 항이 학습되는지) |

# 4. GNN — 그래프 신경망 입력/출력

R-GCN 의 입력 구성 + 정책 마스킹.

| # | 변수 | 입력 ← | 역할 |
|---|---|---|---|
| 1 | KG 동적 4 슬롯: `is_ready`, `bom_satisfied`, `worker_util`, `time_since_eligible` | 각각 §1 의 변수 + env.now | dynamic feat (`build_H_dynamic`) |
| 2 | `_eligible_since` | 직전 값, `is_ready` 전이, env.now | `time_since_eligible` 계산용 sentinel |
| 3 | `H` (per model) | static feat (cycle_time, defect_rate, rated_kw, bom_count, is_join) + `pg_emb[pg_idx]` + `line_emb[line_idx]` + dynamic 4 | R-GCN 입력 (N, in_dim) |
| 4 | `adj_relations[0..4]` | `KG._build_edges()` 의 (src, dst, relation) — `R_FWD_JOIN/SEQ`, `R_BWD_JOIN/SEQ`, `R_SELF` | R-GCN edge type 별 (N, N) — reset 1회 static |
| 5 | `embedding` | `gnn.graph_embed(H, adj)` = ReLU(A·H·W1) → ReLU(A·H1·W2) → mean pool | critic 입력에 concat, agent.buf 저장 |
| 6 | `line_mask` | `KG.nodes[k].line_idx == caller_line_idx` | 라인별 dispatcher 후보 필터 |
| 7 | `node_scores` (masked) | `gnn.score(H2).squeeze(-1)`, `masked_fill(~mask, -inf)`, `softmax` | 정책 분포 source |

# 5. 교차 의존 (한 변수가 여러 측면에 동시 영향)

이 표가 우선순위의 *진짜 이유* — 위 §1~§4 가 별개 stack 이 아니라 같은 변수를 공유.

| 변수 | simpy | RL | PPO | GNN |
|---|:---:|:---:|:---:|:---:|
| `progress` | 종료 조건 | done_delta | — | — |
| `worker_resources.count` | 점유 | `worker_util` 입력 | — | dynamic feat |
| `stock[item]` | consume/restore | stock_penalty | — | `bom_satisfied` 입력 |
| `wh.violations_count` | (없음) | stock penalty 원료 | — | — |
| `wip.violations_count` | (없음) | wip penalty 원료 | — | — |
| `idle.total_idle` | (없음) | idle penalty | — | — |
| `done`, `in_progress` (unit) | KG 진행 | (없음) | — | `is_ready` 갱신 트리거 |
| `ready_units[(m,pc)]` | dispatch FIFO | (없음) | — | `is_ready` 판정 (>0?) |
| `is_ready` | (없음) | `ready_mask` | — | dynamic feat |
| `reward` | (없음) | 강화 신호 | `agent.buf` 항목 | — |

→ 구현 순서: **§1 (simpy 핵심) 먼저 → §5 의 공유 변수가 자동으로 채워짐 → §4 (GNN 동적 feat) → §2 (reward) → §3 (PPO 학습)**.

# AAS `DynamicParameters` SMC 표현 대상

ReferenceElement chain 으로 입력 의존을 명시할 가치 있는 변수만 (= **시뮬 동작의 입력→출력 contract**).

| Dynamic Parameter           | 입력 ref chain                                                                   | 출력 타입      | 갱신 위치                         |
| --------------------------- | ------------------------------------------------------------------------------ | ---------- | ----------------------------- |
| `bom_satisfied(m, pc)`      | `Warehouse.stock` + `ManufacturingProcess.InputBOM`                            | bool       | dispatcher.tick               |
| `is_ready(m, pc)`           | `KG.Action 분류` + `bom_satisfied` + `UnitState.done` + `worker_util`            | bool       | tick + `_enqueue_newly_ready` |
| `worker_util(group)`        | `WWM.WorkstationConfigurationRecords` (capacity) + `Resource.count`            | float[0,1] | tick                          |
| `time_since_eligible(node)` | `is_ready` + `env.now` + `_eligible_since`                                     | float      | tick                          |
| `stock_violation_delta`     | `Warehouse.violations_count` (현재 − prev) + `BOMCategory.MinStock × OrderRatio` | int        | reward()                      |
| `wip_violation_delta`       | `WIPTracker.violations_count` (현재 − prev) + `WIPTracker.cap`                   | int        | reward()                      |
| `idle_penalty_delta`        | `IdleTracker.total_idle` × `WORKER_GROUPS` × `_work_seconds_between`           | float      | reward()                      |
| `energy_delta`              | `EnergyLogger.total` (현재 − prev) + `RatedPowerKw × cycle_time`                 | float      | reward()                      |
| `done_delta`                | `progress` (현재 − prev) + `order`                                               | int        | reward()                      |
| `state_vector`              | 위 모두의 정규화 합성 + `T_REF`, `total_order`, `len(wres)` 분모                          | np.array   | act 직전                        |
| `reward`                    | delta 6항 × `RewardWeights.{W1..W6}`                                            | float      | reward()                      |

**제외**: §6 의 로그·모니터 전부, PPO 학습 버퍼 (§3#1~4), `_prev_*` (§2#5 reward 내부 디테일), simpy 자체 상태 (§1#2 의 `.queue`).

# 비고

- 입력 파라미터 4 분류: **AAS 정적** / **다른 동적 변수** / **simpy 상태** / **`random`·wall-clock**. AAS DynamicParameters 의 ref chain 에는 앞 두 종류만 표현 — random/wall 은 시뮬 구현 디테일.
- `aas_architecture.py` 가 `path_extractor.py` 로 이관된 상태이므로, AAS dataclass 정의는 `path_extractor.py` 에 추가/수정.
- `cap[group]` (WIP), `worker_capacity`, `adj_relations` 는 reset 1회 set 이후 static — 엄밀히는 동적 아님. 입력 의존이 reset 시점에 1회 해소되면 그 후 시뮬 진행과 무관.
