# CPRO 시뮬레이션 실행 API

POST 1개 + 대시보드별 GET 6개. 모델별 PO 수량·납기일을 넣으면(값은 AAS PurchaseOrder 에 기록)
시뮬레이션이 돌고, 각 GET 은 해당 대시보드를 **가공 없이 그대로** 그릴 수 있는 데이터를 준다.

- Base URL: `http://{host}:{port}/api/v1`
- 응답은 모두 JSON. 오류는 `{"error": {"type", "message", ...}}`.
- **시간은 전부 시뮬레이션 경과 시간 `dd:hh:mm`** (t=0 부터. 휴게·비근무 시간 포함, 구간 생략 없음).

## 기동

```
pip install -r requirements-infer.txt fastapi uvicorn
uvicorn api.main:app --host 0.0.0.0 --port 8000
```

환경변수(선택): `CPRO_AAS_DIR`, `CPRO_CKPT`, `CPRO_WORKERS`, `CPRO_JOB_TIMEOUT_SEC`,
`CPRO_SEED`, `CPRO_SAMPLE_SEC`(샘플링 주기 초, 기본 1800 = 00:00:30).

## POST /api/v1/PO-납기일

```
{"모델별 PO 수량":    {"MODEL_A": 180, "MODEL_B": 180, "MODEL_C": 180},
 "모델별 납기일(day)": {"MODEL_A": 3, "MODEL_B": 3, "MODEL_C": 3}}
```

- 값은 AAS(PurchaseOrder)에 기록된 뒤 시뮬레이션이 실행된다 → 202 `{"상태": "running"}`.
- 같은 입력의 완료 결과가 있으면 200 + `X-Cache: hit` (즉시 GET 가능). `?force=true` 로 재실행.
- 모델 추가/삭제는 불가(학습된 모델셋 고정).
- 완료 확인: `GET /api/v1/PO-납기일-현재-등록값` 폴링 — `상태` 가 `done` 이면 대시보드 GET 가능.
  (대시보드 GET 을 바로 폴링해도 됨 — 실행 중엔 202, 완료 시 200)

## GET /api/v1/PO-납기일-현재-등록값

지금 대시보드 GET 들이 보여주는 실행의 PO 수량·납기일과 실행 상태.

```
{"상태": "done",
 "모델별 PO 수량":    {"MODEL_A": 180, "MODEL_B": 180, "MODEL_C": 180},
 "모델별 납기일(day)": {"MODEL_A": 3, "MODEL_B": 3, "MODEL_C": 3}}
```

- `상태`: `running`(실행 중) / `done`(완료) / `failed`(실패).
- 실행 이력이 없으면 404.

## 대시보드 GET 6개

모든 응답은 공통으로 `샘플링 주기(dd:hh:mm)` 와 시간축 `시뮬레이션 시간(dd:hh:mm)` 을 담고,
대시보드 데이터 키가 하나씩 추가된다.

- 공통 쿼리 파라미터 `?샘플링주기_분={1~1440}` (선택) — 생략 시 실행 때 저장된 기본 주기
  (`CPRO_SAMPLE_SEC`, 기본 30분). 지정하면 시뮬을 다시 돌리지 않고 저장된 원자료를
  해당 주기로 즉석 재집계해 응답한다.

| 경로 (`/api/v1/dashboard/실시간/` 하위) | 대시보드 | 데이터 키 |
|---|---|---|
| `모델별-누적-생산량` | 1. 모델별 생산량 | `모델별 누적 생산량` {모델: [개]} |
| `작업자-라인별-점유비율` | 2. 라인별 점유비율 | `라인별 작업자 점유비율` {라인: [0~1]} |
| `생산진행수량` | 3. 생산 진행 수량 | `생산 진행 수량` [개] |
| `생산진행수량-모델별` | 3b. 〃 (모델별) | `모델별 생산 진행 수량` {모델: [개]} |
| `가동-전력` | 4. 공장 가동 전력 | `공장 가동 전력(kW)` [kW] |
| `전력-사용-비율` | 5. 전력 사용 비율 | `전력 사용 비율(%)` — 3종 (아래) |

- 라인명: `FwInputLine`, `LensHolderLine`, `FocusLine`, `SemiAssemblyLine`, `SetAssemblyLine`,
  `InspectionLine`, `AgingLine`, `OqcLine`, `RMALine`, `PackagingLine`.
- 점유비율 = 각 시점 기준, 해당 라인에 배정된 작업자의 동시 작업 용량(작업자 수 × 1인 동시
  담당 수량) 중 공정 진행에 사용 중인 비율 (0~1). 대부분의 라인은 1인 1대 작업이라 "진행 중인
  작업자 비율"과 같고, AgingLine 처럼 1인 다대 담당 라인은 담당 가능 수량까지 반영한다.
  비근무 시간 구간은 0.
- 생산 진행 수량 = 생산에 착수했으나 최종 공정까지 완료되지 않은 수량.

### 전력 사용 비율 — 3종

각 항은 시작~해당 시점 누적 에너지 기준 비율(%). 시점별로 그대로 그린다.

```
"전력 사용 비율(%)": {
  "전체":       {"조립 공정": [...], "SMT 공정": [...], "기저 부하": [...]},
  "조립 라인별": {"FwInputLine": [...], ..., "PackagingLine": [...]},
  "SMT 설비별":  {"Loader": [...], "ScreenPrinter": [...], "Mounter": [...],
                 "AOI": [...], "Reflow": [...], "SPI": [...], "Unloader": [...]}
}
```

- 각 항목의 합계 = 100%. 분모: `전체` = 총 에너지, `조립 라인별` = 조립 공정 에너지,
  `SMT 설비별` = SMT 공정 에너지. (에너지가 아직 없는 초기 구간은 0)

### 예시

```
GET /api/v1/dashboard/실시간/모델별-누적-생산량
{"샘플링 주기(dd:hh:mm)": "00:00:30",
 "시뮬레이션 시간(dd:hh:mm)": ["00:00:30", "00:01:00", ...],
 "모델별 누적 생산량": {"MODEL_A": [0, 0, 12, ...], "MODEL_B": [...], "MODEL_C": [...]}}
```
